# Platform Integration Test Framework

## Purpose

This framework validates the complete Robot Platform pipeline:
Robot Program → Compiler → Bytecode → Program Loader → Virtual Machine → Instruction Dispatcher → RobotApiDispatcher → ESP32RobotApi → HAL → Hardware

text

It ensures that the entire system works end-to-end.

## Architecture

The integration tests use the existing Python runtime (which includes a mock hardware implementation) to execute compiled programs and verify their behavior.

Each test:

1. Compiles a RoboSim/Standard Robot API program using the compiler.
2. Loads the generated bytecode into the Virtual Machine.
3. Executes the program.
4. Verifies the output (motor commands, sensor readings, LED state, etc.) against expected results.

## Running Tests

From the repository root:

```bash
python tests/integration/runner.py
Options:

--verbose or -v for detailed output.

--json to output results in JSON format.

--test to run a specific test (e.g., --test motion).

Adding Tests
Create a new Python file in tests/integration/ named test_<name>.py.

Define a function run_test() that returns a dictionary with keys passed, message, and optionally metrics.

The runner will discover and execute it.

Test Categories
Motion: Forward, backward, turn, stop, speed control.

Sensor: Ultrasonic, touch, light, line, color.

Control: If, while, nested loops, jumps.

Output: LED, buzzer.

Timing: Wait and delays.

Obstacle Avoidance: Complex scenario.

Compile-Execute: End-to-end compile and execute.

Expected Outputs
Tests produce a summary report with:

Pass/Fail status.

Execution time.

Instruction count.

RobotAPI calls.

Detailed logs (if verbose).

Troubleshooting
Ensure Python dependencies are installed (click, pyyaml, etc.).

If tests fail, check the compiler and runtime code for regressions.

Use --verbose to see detailed execution logs.

Future Extensions
Add real hardware validation (ESP32) by using a serial interface to capture logs.

Integrate with CI/CD for automated regression testing.
