# 1. Purpose

This document defines the **official language specification** of the Python source code generated by RoboSim.

This specification is **NOT** a Python language specification.

Instead, it defines a **Robot Domain Specific Language (Robot DSL)** whose syntax happens to be Python.

The Robot Compiler only guarantees compatibility with this specification.

Anything outside this specification is considered **unsupported**.

---

# 2. Design Philosophy

The compiler does not compile generic Python.

Instead, it compiles RoboSim generated programs.

```
          RoboSim
              │
              ▼
      Robot DSL (Python Syntax)
              │
              ▼
          Frontend AST
              │
              ▼
          Robot IR
              │
              ▼
          Robot Bytecode
              │
              ▼
         Runtime / VM
              │
              ▼
          Robot Hardware
```

The language is intentionally **small**, **predictable**, and **deterministic**.

---

# 3. Language Characteristics

The language is:

- Procedural
- Imperative
- Static structure
- Deterministic
- Hardware-oriented

The language is NOT:

- Object-oriented
- Functional
- Dynamic
- Reflective
- Meta-programming capable

---

# 4. File Structure

Every RoboSim program follows this structure.

```
Import

Global Constants (optional)

Function Definitions

Thread Startup

Main Loop
```

Example

```python
import rcu
import _thread

def task1():
    ...

def task2():
    ...

_thread.start_new_thread(task1,())
_thread.start_new_thread(task2,())

while 1:
    pass
```

---

# 5. Supported Imports

Currently supported imports:

```
import rcu
import _thread
```

Future imports require compiler support.

Wildcard import is forbidden.

```
from xxx import *
```

Unsupported.

---

# 6. Global Variables

Supported.

```
SERVO_PORT = 1

SPEED = 70
```

Must be compile-time constants.

---

# 7. Function Definition

Supported.

```
def mission():
    ...
```

Nested functions are not supported.

Recursive functions are not supported.

Function pointers are not supported.

---

# 8. Function Call

Supported.

```
mission()

gripper_pick()
```

Compiler resolves function addresses statically.

# 13. Assignment

Supported.

```

```

---

# 14. If Statement

Supported.

```
if sensor > 50:
    ...

else:
    ...
```

Nested if is supported.

elif is rewritten internally.

---

# 15. While Loop

Supported.

```
while True:
    ...

while 1:
    ...
```

Condition loop supported.

```
while sensor > 50:
    ...
```

---

# 16. For Loop

Only this syntax is supported.

```
for i in range(10):
```

Optional

```
range(start,end)

range(start,end,step)
```

---

# 17. Thread

Supported syntax

```
_thread.start_new_thread(...)
```

Execution model depends on runtime.

Compiler only records thread entry functions.

---

# 18. Pass

Supported.

```
pass
```

Compiled into NOP.

# 21. Robot API

Robot APIs are NOT Python functions.

They are compiler intrinsic functions.

Example

```
rcu.SetMoveRun(...)
```

Compiler recognizes them directly.

No Python runtime dispatch exists.

---


# 23. Program Entry

Program starts at module scope.

Example

```
robot_initialize()

_thread.start_new_thread(...)

while 1:
    ...
```

There is no

```
main()
```

---

# 24. Execution Model

Compiler transforms source into

```
Module

↓

Functions

↓

Instructions

↓

Bytecode
```

Runtime executes bytecode.

Python interpreter is NOT required.

---

# 25. Language Boundary

The compiler guarantees support only for code generated by RoboSim.

User-written Python outside this specification is undefined behavior.

---

# 26. Compatibility Goal

The compiler aims for

```
100% RoboSim Compatibility
```

NOT

```
100% Python Compatibility
```

---

# 27. Compiler Responsibility

Compiler is responsible for

- Syntax parsing
- Semantic validation
- API recognition
- IR generation
- Bytecode generation

Compiler is NOT responsible for

- Motion control
- PID
- Line following
- Servo algorithm
- Sensor filtering

Those responsibilities belong to Robot Runtime.

---

# 28. Runtime Responsibility

Runtime implements Robot APIs.

Example

```
MOVE_FORWARD

↓

RobotAPI::MoveForward()

↓

Motor Driver
```

The compiler never expands high-level robot algorithms.

---

# 29. Compatibility Principle

Whenever RoboSim evolves,

the language specification evolves first,

then

- API Spec
- Frontend
- Compiler
- VM
- Runtime

must follow.

The specification is the single source of truth.

---

# 30. Success Criteria

The language implementation is considered complete when:

- Every RoboSim generated program parses successfully.
- Every supported AST node compiles successfully.
- Every Robot API resolves successfully.
- Generated bytecode executes correctly.
- Robot behavior matches RoboSim simulation.

Only then is RoboSim Compatibility considered **100%**.
